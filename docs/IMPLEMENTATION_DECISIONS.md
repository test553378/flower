# 実装時の仕様決定

優先する文書は `おはなやさんゲーム_要件定義書_Ver1.1.md`。以下の8項目は、実装前の質問に対してユーザーが「8項目すべて提案どおり」と回答し承認した内容です。

| 要件 | 承認内容 |
|---|---|
| OPEN-01 | 左にお客さん・注文、中央に花束、右に花選択／ラッピングを切り替えるパネル。注文と花束は常に表示する。 |
| OPEN-02 | 同一注文の再登場は許容する。他の実現可能な注文がある場合は連続の重複を避ける。 |
| OPEN-03 | 2本以上はすべて包装紙・リボンの選択必須。1本販売はラッピングなし。自由制作は1〜10本でラッピングする。 |
| OPEN-04 | コレクション数はアプリ上の上限なし、1ページ6個、前後のページ切り替え。端末メモリの物理的な制約はある。 |
| OPEN-06 | 登場約0.4秒、正解・会計約1.5秒、クリアは「つぎへ」まで表示。短く穏やかな演出。動きを減らす端末設定にも対応。 |
| OPEN-07 | 当初はPR提示とPages設定追加まで。後続のユーザー指示「ページの公開まで自動で進めて下さい」により公開も実行する。GitHub接続ツールはPages管理APIに対応しないため、SitesでURLを公開する。GitHubには実装PRも作成する。 |
| OPEN-08 | Safari終了時の消去保証は求めない。再読み込み・確認付きタイトル復帰で進行とコレクションを初期化。 |
| OPEN-09 | 音設定はタイトル復帰時に維持。再読み込み時は3項目すべてオン。 |

## 技術選定

既存リポジトリには素材と文書のみで、アプリ・既存フレームワークはありませんでした。JavaScript ES Modules、HTML、CSSを採用。実行時の外部依存はなく、iPad Safariが直接読み込む静的サイトです。Node.js 22以上は開発・テスト・ビルドだけで使用します。happy-domは開発用のDOM操作テストにのみ使用します。

- `catalog.js`: 品種・色・価格・素材パス、ステージ初期在庫。
- `logic/orders.js`: 在庫内の注文候補、難易度、連続重複回避。
- `logic/inventory.js`: 本数・価格・在庫減算。
- `logic/validation.js`: 種類×色×本数の照合と差分ヒント。
- `logic/state.js`: 販売・会計・遷移・自由制作の状態更新。
- `bouquet.js`: 1本ごとの画像、包装紙の前後レイヤー、リボンの動的合成。
- `audio.js`: オリジナルBGM・効果音とWeb Speech API。
- `app.js`: HTML表示、タップ、確認ダイアログ、6個ごとのページ送り。

注文の目標本数はステージ開始時2/3/4/5/5本、客順に応じて本数・種類数を増やし、最大5本に収めます。難易度は在庫完売を優先するため厳密な単調増加ではありません。候補は在庫以内の全組み合わせから選び、正解まで固定します。正解ごとに最低1本減るため、初期在庫の本数以下の販売回数で必ず完売します。

## 音の制作方法

BGM・効果音のファイルは追加していません。`audio.js`に今回作成した32音の旋律と低音パターンを記述し、Web Audio APIの正弦波・音量エンベロープでその場で生成します。操作・取り消し・正解・クリア・自由制作の完成・ヒントは別々の短い音列です。既存曲の音源・第三者サンプルは使いません。BGMは低音量、読み上げ中はさらに低くします。

Safariの制限を考慮し、ユーザーのタップ内でAudioContextを作成／再開します。BGM・効果音・声は独立したオン／オフを持ちます。読み上げは毎回cancelしてからspeakし、終了コールバックの世代も管理します。日本語音声の一覧がまだ空でもlang=ja-JPで再生を試みます。日本語音声が使えなくても注文文を表示しゲームを継続します。バックグラウンド・ページ離脱では音を停止し、復帰後は次のタップで音楽を再開します。

## 素材

台帳の個別PNG61点は変更していません。すべてを先読みし、欠損を検出した場合は案内を表示します。実ゲームの花束に完成見本PNGは使わず、選択データと同数の花レイヤーを生成します。販売棚・花束・ヒントは同じcatalogの画像を参照します。

台帳にもある通り、表情・花・リボン等には切り出し拡大された素材が含まれます。ハッシュやPNG形式の検証は画質の保証とは異なり、細部のにじみ、透過輪郭、重なりの自然さはiPad実機で確認が必要です。
